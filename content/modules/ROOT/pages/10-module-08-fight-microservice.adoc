= Module 8: The Fight Microservice with Generative AI
:source-highlighter: rouge
:toc: macro

Here is the grand finale! OpenCodeQuest Corp wants the fights to be decided by **Artificial Intelligence** -- not by a simple random calculation. The Fight service will query a **Large Language Model (LLM)** hosted on **Red Hat OpenShift AI** to decide the winner and generate an epic fight narration.

Thanks to **Quarkus LangChain4j**, integrating an LLM into a Java application is as simple as adding a few annotations.

== Fight service architecture

The Fight service is the orchestrator service of the application. It:

. Retrieves a random hero from the Hero service
. Retrieves a random villain from the Villain service
. Sends both profiles to the LLM with a prompt describing the fight
. Receives the result (winner + narration) from the LLM
. Returns the result to the Fight UI interface

== Exercise 3: Define the AI Service

The Quarkus LangChain4j extension provides a declarative approach to interact with LLMs via the `@RegisterAiService` annotation.

. Open `src/main/java/io/quarkus/workshop/fight/FightSimulatorService.java`.

. Replace the content with the AI Service interface:
+
[source,java]
----
package io.quarkus.workshop.fight;

import dev.langchain4j.service.SystemMessage;
import dev.langchain4j.service.UserMessage;
import io.quarkiverse.langchain4j.RegisterAiService;
import io.smallrye.faulttolerance.api.Timeout;
import jakarta.enterprise.context.ApplicationScoped;

import java.time.temporal.ChronoUnit;

@RegisterAiService
@ApplicationScoped
public interface FightSimulatorService {

    @SystemMessage("""
        You are a superhero combat simulator.
        Decide the winner of a fight between a hero and a villain.
        Respond ONLY with valid JSON matching this structure:
        {
            "winner": "hero" or "villain",
            "narration": "An epic description of the fight in 2-3 sentences."
        }
        """)
    @UserMessage("""
        <|system|>
        You are a superhero fight simulator.
        <|user|>
        Simulate a fight between:
        Hero: {hero}
        Villain: {villain}
        Who wins and why? Respond in JSON only.
        <|assistant|>
        """)
    @Timeout(value = 1, unit = ChronoUnit.MINUTES)
    FightResult fight(Hero hero, Villain villain);
}
----
+
NOTE: The `@RegisterAiService` annotation tells Quarkus to automatically generate the implementation that calls the LLM. You only write the interface and prompts -- Quarkus does the rest.

=== How prompts work

* **`@SystemMessage`**: The system context sent to the LLM that defines its role and the expected response format.
* **`@UserMessage`**: The user request with `{hero}` and `{villain}` parameters -- Quarkus replaces these placeholders with the values passed as method parameters.
* **`@Timeout`**: If the LLM takes more than 1 minute to respond, the call is cancelled (Fault Tolerance via SmallRye).

The LLM responds with JSON that is automatically deserialized into a `FightResult` by Quarkus.

== Exercise 4: Configure the LLM connection

. Open `src/main/resources/application.properties`.

. Add the LLM connection configuration (values provided by your instructor):
+
[source,properties]
----
# LLM configuration on OpenShift AI
quarkus.langchain4j.openai.base-url=${AI_URL:https://your-llm-endpoint}
quarkus.langchain4j.openai.api-key=${AI_KEY:dummy}
quarkus.langchain4j.openai.chat-model.model-name=${AI_MODEL:granite}
quarkus.langchain4j.openai.timeout=60s
quarkus.langchain4j.openai.log-requests=true
quarkus.langchain4j.openai.log-responses=true
----
+
IMPORTANT: Replace `your-llm-endpoint`, `dummy` and `granite` with the values provided by your instructor. These values point to the LLM hosted on OpenShift AI in your cluster.

== Troubleshooting

**Issue**: Fight service returns a timeout error

**Solution**: The LLM may be busy. Wait a few seconds and retry. If the problem persists, verify the LLM URL in `application.properties`.

**Issue**: LLM response is not valid JSON

**Solution**: Adjust the `@SystemMessage` to be more explicit about the expected JSON format. The `@UserMessage` should also guide the LLM toward a structured response.

**Issue**: `ClassCastException` on `FightResult`

**Solution**: Check that `FightResult` is a Java record with `winner` and `narration` fields exactly matching the JSON structure described in the prompt.
